# Privacy and storage — v2

- No account, backend, analytics, ads or telemetry. The selected public platform and CDN receive the IP address and requests necessary to retrieve user-requested media. The app configures TLS verification and rejects remote plaintext transfers.
- New media and pending files are stored inside the application's internal files/cache directories. Room history is private; Android backup is disabled. Engine files are in app-private no-backup storage. No shared Downloads/MediaStore/SAF destination is used in this version.
- The original public page URL, title, format selection ID, MIME, file URI, status/counters/timestamps and preferences are stored. Extracted signed stream URLs and limited User-Agent/Referer/Origin headers are ephemeral, not written to Room. No cookie-file import, account login, password, authorization header or session-token history is supported.
- The native extractor is configured behind a per-session authenticated loopback CONNECT gate. The local control connection is HTTP on loopback; remote allowed connections tunnel TLS/443 to checked public addresses. No local backend service is exposed on public interfaces. Proxy credentials and raw extractor stderr are not logged.
- FileProvider is not exported, has only a private `media/` root, and grants temporary per-URI read access after explicit Open/Share. A chosen recipient can retain a copy once the user shares it; a temporary grant is not revocation of already copied data.
- Delete asks for confirmation and removes the file/history entry. Clearing history removes terminal records while keeping private files; that loses their in-app management entries. Clearing application data or uninstalling removes private data/files. Export/share required files first.
- TLS, public-host checks, bounded subprocess output and bounded media buffers reduce specific risks. They do not certify every URL or native file parser as harmless, or hard-limit the entire embedded Python/JavaScript process RSS. Android native initialization, actual storage grants, real TLS behavior and device memory usage remain unverified pending an Android build/device test.
